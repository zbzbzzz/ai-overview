# 资讯重要度加入「资讯热度」维度

资讯重要度原来只有行业冲击 50%、可动手 35%、覆盖面 15%，同一事件被多少家报道、社区讨论多热完全不计，导致只有一篇曝光稿的条目和被十几家跟进的发布难以区分；同时旧的「覆盖面」常被顺手当成报道篇数，含义混乱。

现改为四维：行业冲击 40%、可动手价值 30%、资讯热度 20%、覆盖面 10%。资讯热度 = 束内去重报道篇数 + 跨站转载（去重站点数）+ X 近 7 天新增讨论量（`get_posts_counts_recent`，总帖数减 7.5×事件前日基线，抵消常用词噪音）；公式见 GLOSSARY「资讯热度」，`generate.py` 的 `heat_score()` 与之一致。X 调用量保持克制（每次刷新约每束 1 次，上限 30/分钟、1000/天）；X 不可用或未查时只按篇数与站点数算。覆盖面改为只指受影响人群/场景广度。

热度必须在资讯束拆分/合并正确之后计算（见 ADR 0013 修订），否则误并会虚增热度。`score_parts` 新增 `heat`，`news-model-scores.json` 同步记录 `heat` 和 `heat_signals`（reports / domains / x_posts_7d / x_spike_7d）。旧数据缺 `heat` 时生成器按外链数补算。

动态重点规则（ADR 0015：前 3 必选，第 4、5 名 ≥ 85）不变。新分布下 64 个资讯束中位数 63.1，≥ 85 的有 4 个（旧分布为 5 个，中位数 71.7）；85 仍只放行明显头部事件，暂不调整。
